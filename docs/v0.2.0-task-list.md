# v0.2.0 任务清单 — 批量数据库架构评审

> 设计依据：`docs/v0.2.0-design.md` · 约定：参考驱动（复用现有 rules/practices/metrics/UI 组件）· 迭代式：先打通链路，再补规则与 UI 细节。
> 任务编号 TASK1–TASK12。每个任务含子任务与验收标准（AC）。

---

## TASK1 — 虚拟数据字典（VDD）数据模型
- 1.1 新建 `backend/schema_model.go`：定义 `SchemaModel / TableDef / ColumnDef / IndexDef / Reference / ObjectSource / ParseNote / SchemaFinding`（见设计 §2）。
- 1.2 实现表名规范化 `normalizeIdent(name, dialect)`：兼容 `` `t` `` / `[dbo].[t]` / `"schema"."t"` / `db.t`，统一小写 key，保留 `QualifiedName`。
- 1.3 实现 `SchemaModel` 的累加方法：`AddTable / AddColumn / AddIndex / AddReference / MergeAlter`。
- 1.4 编写 JSON 序列化测试（字段完整、无循环引用）。
- **AC**：`go test -run TestSchemaModel` 通过；4 方言表名规范化各有测试。

## TASK2 — DDL 提取器（schema_lex）
- 2.1 复用 `lex.go` 的 Token/tokenize，新建 `backend/schema_lex.go`。
- 2.2 识别语句：`CREATE TABLE` / `CREATE [UNIQUE] INDEX` / `ALTER TABLE ...` / `COMMENT ON` / 内联与表级 `FOREIGN KEY`。
- 2.3 解析列定义：类型、长度/精度、NULL、DEFAULT、AUTO_INCREMENT/IDENTITY、COMMENT。
- 2.4 解析表级属性：PRIMARY KEY、UNIQUE、KEY/INDEX、ENGINE/CHARSET/COLLATE、PARTITION。
- 2.5 解析 `ALTER TABLE` 动作：ADD/DROP/MODIFY/CHANGE COLUMN、ADD/DROP INDEX/KEY/PK/FK，按文件顺序合并。
- 2.6 收集 `PredicateUsage`：从 SELECT/DML 的 WHERE/JOIN/ORDER BY 提取列引用（供 ARCH023）。
- 2.7 无法解析的语句写入 `ParseErrors`，不中断。
- **AC**：4 方言各 ≥5 个 DDL 样例（含 ALTER 合并）；解析失败不 panic；`go test -run TestSchemaLex` 通过。

## TASK3 — 架构规则引擎骨架
- 3.1 新建 `backend/schema_review.go`：`SchemaRule` 接口/meta、`SchemaRuleCatalog`（ARCH 命名空间）、`RunSchemaReview(model, cfg)`。
- 3.2 规则配置复用 `RuleConfig`：`disabled` / `severity` 覆盖；新增 `schemaRules` 子配置（可选）。
- 3.3 实现统一 `add()`：去重（同 rule+表+文件）、按严重度排序、每规则 50 条上限并聚合"另有 N 条"。
- 3.4 实现 `ArchitectureReport`（score/grade/findings/tables/indexes/suggestions/stats）。
- **AC**：规则框架可注册空规则并产出报告；配置开关生效。

## TASK4 — 表设计规则（ARCH001–ARCH009）
- 4.1 实现 9 条表设计规则（见设计 §3.1）。
- 4.2 方言分支：主键策略（MySQL 有序 BIGINT / PG IDENTITY / SQLite rowid / SQLServer 聚簇键）、字符集、引擎。
- 4.3 关联 `practiceIds`（BP-MY-001/BP-PG-004/BP-LT-001 等）。
- **AC**：每条规则 ≥1 正例 + 1 反例单测。

## TASK5 — 列与类型规则（ARCH010–ARCH015）
- 5.1 实现跨表同名列类型一致性检测（按规范化列名建索引，类型归一化后比较）。
- 5.2 金额浮点、大字段、可空无默认值、PG 时区/JSONB 规则。
- 5.3 误报缓解：低严重度 + 文案"确认是否业务故意"。
- **AC**：构造 2 表 user_id 类型不一致样例能命中 ARCH010；金额 FLOAT 命中 ARCH011。

## TASK6 — 索引设计规则（ARCH016–ARCH024）
- 6.1 索引名重复、冗余前缀索引、低区分度、索引过多、外键列无索引。
- 6.2 表达式索引、复合索引顺序启发式、命名规范。
- 6.3 **ARCH023 谓词覆盖缺口**：基于 TASK2 的 `PredicateUsage` 与 VDD 索引列做集合差，输出高频过滤列无索引。
- **AC**：`(a)` 与 `(a,b)` 并存命中 ARCH017；JOIN 列无索引命中 ARCH023；动态 SQL 列不误报。

## TASK7 — 关系完整性与迁移安全规则（ARCH025–ARCH032）
- 7.1 外键目标表缺失、隐式引用、循环检测（邻接表 + DFS）、CASCADE 风险。
- 7.2 NOT NULL 无默认值、在线索引汇总、单文件多表变更、重复定义。
- **AC**：构造循环 FK 命中 ARCH027；重复 CREATE TABLE 命中 ARCH032。

## TASK8 — 架构评分与建议生成
- 8.1 `ArchitectureReport.Score` 复用 v0.1.32 同规则递减计分算法（提取公共函数 `penaltyScore(findings)`）。
- 8.2 等级映射 A+/A/B/C/D/E（复用 `gradeOf` 或独立实现，不改变六维质量分）。
- 8.3 按表聚合建议卡：正反 DDL 片段、关联规则与最佳实践、源文件位置。
- 8.4 建议上限与截断策略。
- **AC**：同类问题重复 6 次不再把分数打到 0（继承 v0.1.32 修复）；建议卡按表聚合且含 `goodSql`/`badSql`。

## TASK9 — 批量链路集成（后端）
- 9.1 `runBatch` 在逐文件评审 + 一致性校验之后，调用 `BuildSchemaModel(results) → RunSchemaReview()`（新增阶段与进度上报）。
- 9.2 `BatchReport` 新增 `Architecture *ArchitectureReport json:"architecture,omitempty"`。
- 9.3 新增 API：`batch/architecture`、`batch/architecture/export`、`schema/review`（直接传多文件文本）。
- 9.4 `batch/file` 返回 `suggestedPractices`（调用 `withPractices`）。
- 9.5 `config` 新增开关 `schemaReview.enabled`、`wideTableColumns`，并提供 `--skip-architecture` 回退。
- **AC**：`batch/run` 返回 architecture 且旧字段不变；186 文件基线 <30s；关闭开关后行为与 v0.1.33 一致。
